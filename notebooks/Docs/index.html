1. Preparación del entorno

Antes de empezar, asegúrate de tener instalado:

  • Python 3.9 o superior
  • Un editor de código (VS Code recomendado)
  • Jupyter Notebook o Jupyter Lab (para ejecutar los notebooks)

Instalar las librerías

Abre tu terminal/PowerShell y ejecuta:

pip install duckdb pandas openpyxl jupyterlab

2. Entender el problema y la solución

El problema: Tienes un archivo Excel con 41,342 filas de despachos aduanales que es imposible analizar directamente.

Problemas del Excel original:
  • ❌ Espacios en blanco en nombres de columnas
  • ❌ Fechas escritas como texto
  • ❌ Información repetida (país aparece 10,000 veces)
  • ❌ Lento de procesar

La solución: Construimos un Data Warehouse: una base de datos especial para análisis.

Ventajas del DW:
  • ✅ Datos limpios y organizados
  • ✅ Sin repeticiones innecesarias
  • ✅ Optimizado para análisis
  • ✅ Rápido y confiable

3. Crear la estructura de las tablas

Notebook a ejecutar: 01_Crear_Estructura_DW.ipynb

Creamos 15 tablas vacías siguiendo un diseño Star Schema:

  • 1 tabla de staging
  • 12 tablas de dimensiones
  • 1 tabla de hechos
  • 1 tabla de auditoría

4. Cargar y limpiar los datos

Notebook a ejecutar: 02_Cargar_Staging.ipynb

Este paso es crucial. Aquí limpiaremos el Excel:

  1. Quitamos espacios de nombres de columnas
  2. Convertimos fechas de texto a fechas reales
  3. Normalizamos los datos
  4. Guardamos en stg_aduana

5. Crear las dimensiones

Notebook a ejecutar: 03_Cargar_Dimensiones.ipynb

Creamos catálogos únicos (sin repeticiones):

Dimensión Filas aprox.
dim_operacion 2
dim_pais 50+
dim_producto 500+
dim_fecha 365-730

6. Crear la tabla de hechos

Notebook a ejecutar: 04_Cargar_Fact_Table.ipynb

El paso más importante: creamos la tabla central conectando todo mediante 14 JOINs.

7. Validar la integridad

Notebook a ejecutar: 05_Validaciones.ipynb

Asegúrate de que todo está bien:

  • ✓ No hay claves huérfanas
  • ✓ No hay duplicados
  • ✓ No hay valores negativos absurdos
  • ✓ Las fechas tienen sentido

8. Conectar a Power BI

Finalmente, conectas tu DW a Power BI y creas reportes interactivos.

¡Listo! Tienes un Data Warehouse profesional listo para análisis.

⚡ Quick Start — DWH en 20 minutos

Si no tienes mucho tiempo y quieres entender el flujo rápido...

El problema en 30 segundos

Tienes un Excel gigante con datos de aduanas. Quieres analizarlo en Power BI pero está:

  • ❌ Lleno de espacios y caracteres raros
  • ❌ Datos repetidos (BRASIL aparece 10,000 veces)
  • ❌ Fechas como texto, no como fechas reales
  • ❌ Muy lento de procesar

La solución en 30 segundos

Construimos un Data Warehouse: una base de datos especial para análisis donde:

  • ✅ Todo está limpio y normalizado
  • ✅ No hay repeticiones (BRASIL aparece 1 sola vez)
  • ✅ Las fechas son verdaderas fechas
  • ✅ Es rápido y eficiente

Total: ~1:20 h de ejecución

Las 3 ideas clave

1️⃣ ETL: Extraer, Transformar, Cargar

EXTRAER TRANSFORMAR CARGAR (del Excel) (limpiar/unir) (en DuckDB) ↓ ↓ ↓ Lee CSV Quita espacios stg_aduana Convierte fechas dim_* Normaliza fact_*

2️⃣ Star Schema: Una estrella con dimensiones

dim_fecha dim_pais dim_producto │ ────────┼──────── │ │ dim_operacion fact_aduana_item dim_aduana │ │ ────────┼──────── │ dim_regimen

3️⃣ Datos sin repetir: IDs en lugar de texto

❌ MALO: "BRASIL" aparece 10,000 veces

✓ BUENO: El número "5" aparece 10,000 veces

    "5" apunta a "BRASIL" en dim_pais

Comandos útiles (copiar/pegar)

import duckdb

# Conectar
con = duckdb.connect('db/aduana.duckdb')

# Ver cuántas filas
con.query('SELECT COUNT(*) FROM stg_aduana').show()
con.query('SELECT COUNT(*) FROM fact_aduana_item').show()

# Ver las primeras 5 filas
con.query('SELECT * FROM dim_pais LIMIT 5').show()

# Análisis rápido
con.query('''
SELECT 
    operacion,
    COUNT(*) as total,
    SUM(fob) as total_fob
FROM fact_aduana_item
GROUP BY operacion
''').show()

2. Las 4 capas de datos

Capa Nombre Descripción Uso
1 Bronze Datos crudos tal como vienen (Excel, CSV) Auditoría, trazabilidad
2 Silver Datos limpios (staging) Análisis ad-hoc
3 Gold Datos listos para análisis (dimensiones + fact) Reportes, BI, análisis

3. Star Schema explicado

El diseño central de nuestro DW:

  • Una tabla central (Fact): fact_aduana_item con 41,342 filas
  • Tablas de referencia (Dimensions): 12 tablas sin repeticiones
  • Relaciones (ForeignKeys): Conectan fact con cada dimensión
Ventajas del Star Schema:
✓ Menos repeticiones (base de datos pequeña)
✓ Consultas rápidas
✓ Fácil mantenimiento
✓ Ideal para Power BI

Preguntas frecuentes

¿Necesito saber SQL?

No, pero ayuda. Los notebooks tienen SQL comentado. Aprenderás mientras lo ejecutas.

¿Puedo modificar los datos?

Sí, totalmente. El proyecto está diseñado para ser extensible.

¿Funciona en Windows/Mac/Linux?

Sí. Python y DuckDB funcionan en los tres. Power BI solo en Windows/Web.

¿Cuánto espacio ocupa?

El archivo aduana.duckdb ocupa ~20-50 MB. Los CSVs originales dependen del tamaño.

¿Qué hago si algo falla?

Consulta la sección "Troubleshooting" en la Guía Paso a Paso o el Índice General.

Preguntas para los alumnos

Conceptuales

  1. ¿Por qué no guardamos directamente el texto en la fact table?
  2. ¿Qué pasaría si alguien cambia el nombre de una aduana en los datos?
  3. ¿Por qué dim_pais se usa dos veces en la fact table?
  4. ¿Qué ventaja tiene el modelo Star Schema?

Técnicas

  1. ¿Qué devuelve `SPLIT_PART('BRA - BRASIL', ' - ', 2)`?
  2. ¿Diferencia entre `DELETE FROM` y `DROP TABLE`?
  3. ¿Qué pasa si hay un valor que no está en la dimensión?
  4. ¿Por qué se usa `COALESCE(campo, '')` en el JOIN?

Errores comunes y cómo explicarlos

"Connection already closed!"

Causa: se llamó `con.close()` y luego se intentó usar `con` de nuevo.

Lección: la conexión es un recurso que hay que abrir y cerrar una sola vez.

Analogía: es como colgar el teléfono y tratar de seguir hablando.

"Column not found"

Causa: el nombre de la columna no existe (quizás tiene espacios o mayúsculas).

Solución: ejecuta `df.columns` para ver los nombres exactos.

FK huérfana

Causa: hay un valor que no existe en la dimensión correspondiente.

Lección: la integridad referencial es importante.
